# V0.2 architecture alignment

Design baseline: [CodeCraft hardware architecture V0.2](https://seeedstudio.feishu.cn/docx/QgNjdqDbwotGQcxDKHmcxYMvn6b), updated 2026-11-18, document revision 1430. This is the implementation ledger, not a declaration that every design item already works.

Git baseline: `90a73efdfa7eec792c5c9068edd83d15da6a6d0f`. Work branch: `feat/v0.2/architecture-alignment`. Concurrent V0.1 work was initially left in its original checkout; its later committed changes through `88e7e16` are included in the ordered main-branch integration below. LayerFS checkpoints retain the V0.2 working history; the Git checkout retains reviewable source. Neither a LayerFS checkpoint nor a passing test authorizes Git publication, device writes or cloud operations.

## Accepted scope for this implementation

- User applications may be generated under `projects/<name>`; explicit external output directories remain supported. Reference sources cannot depend on private projects. Application metadata and locks remain local to each project.
- `project.yaml` owns the project brief, including purpose, target users, scenarios and BOM. The marked application AGENTS region is a generated view; custom rules outside it are preserved. Missing information is unknown, never inferred from a similar board.
- User clarification on 2026-11-18: sensecraft-cli is an external tool from [Seeed-Solution/sensecraft-cli](https://github.com/Seeed-Solution/sensecraft-cli); adopt its published package and official Skill directly. This repository maintains setup/routing, with authentication and platform HTTP implementation upstream. The verified platform commands do not replace the separate CodeCraft LLM/ASR/TTS/image-generation APIs, whose existing clients remain current.
- The previous decision to register no simulator remains current behavior, but does not satisfy V0.2's first simulator milestone. A host unit fixture is not a user-project simulator.
